# What could not be exported, dependencies and limitations

## 1. Dependencies on Claude

The app code makes no calls to Claude or Anthropic and needs no Claude session to run. Three small traces remain in `index.html`. They are left exactly as published, because the export must not change the app:

| Trace | Where | Effect outside Claude | Action needed |
| --- | --- | --- | --- |
| `window.claude.use("downloads")` | `poster()` function (clinic poster download) | `window.claude` does not exist, so the app falls back to a normal browser download (`<a download>`). Tested: the poster downloads as `unhookd-clinic-poster.png`. | None. Optionally delete the `window.claude` line in a future edit. |
| `<meta name="claude:viewport-fit-sides" content="cover">` | top of the file | Ignored by browsers. | None. |
| Reset stylesheet in `<head>` | start of the file | Added by Claude's publishing step. Ordinary CSS that is part of the current look. | None. Keep it, or the spacing changes slightly. |

The dormant translation helpers (the language feature was removed) also remain in the file. They do nothing while `S.lang` is `"en"`.

## 2. Things that cannot be exported

| Item | Why | What you have instead |
| --- | --- | --- |
| Data people entered in the Claude-hosted copy | `localStorage` belongs to each browser and web address. It cannot be read from outside that browser, and the app has no export or import feature. | A fresh, empty app on your own domain. "Explore with sample data" still works. |
| Claude artifact sharing, version history and comments | Features of claude.ai, not of the app. | The two published versions are included as files (`index.html`, `versions/v1-earlier-prototype/index.html`). |
| The live Claude Doc "Unhookd: abstract and app description" | It is a document on claude.ai. | A Markdown snapshot in the private backup ZIP (not in this public repository). |
| Project documents in the Claude Project "MIT SOLVE" | They live in claude.ai. | Markdown copies in the private backup ZIP (not in this public repository). |
| Audio files | None exist. Sounds are generated by code (Web Audio). | The sound code is inside `index.html` (`sfx()` function). |
| Image files for illustrations | None exist. All art is SVG drawn by code at run time. | Snapshot SVG files in `assets/illustrations/` (colours resolved for the default Grape theme, day mode). The source of truth stays the JavaScript functions (`buddy()`, `mapSvg()`, `placeSticker()`, `PIC`, `LOGO`). |

## 3. Dependencies on outside services

| Service | Needed for | Without it |
| --- | --- | --- |
| Google Fonts | the Nunito and Baloo 2 typefaces in `index.html` | system fonts (layout still works) |
| cdnjs | drawing the clinic QR image in `index.html` | the code is shown as text and can be copied or sent |

`index-selfhosted.html` removes the first three: it loads fonts and both QR libraries from `vendor/`.

## 4. Features that are simulated or limited in the prototype

These work as shown in the published prototype and are exported unchanged. They are listed so nothing is mistaken for a finished production feature.

- **Pro tier:** turned on with a button, no payment is taken.
- **Discreet reminders setting:** a saved preference only. The prototype does not send push notifications.
- **Fingerprint or face unlock:** uses WebAuthn on the device. It was not tested with a real fingerprint sensor (the test browser has none; the fallback screen was shown and works). It acts as a local unlock only; nothing is verified by a server. It should work on HTTPS sites such as Netlify in browsers that support platform authenticators, but this has not been tested.
- **Camera QR scanning:** uses the phone's camera through a file picker. The photo-decoding path was tested with a generated QR image; scanning with a real phone camera has not been tested.
- **Vibration:** Android browsers only. iPhone Safari does not support vibration from web pages.
- **Read aloud:** depends on the voices installed on the phone.
- **Emergency and helpline numbers:** prototype data that must be checked for each country before real use.
- **Medical and safety text, withdrawal self-check:** general guidance written for the prototype, to be reviewed by a qualified clinician.
- **Security:** data, PIN and recovery words are stored unencrypted in `localStorage`; clinic codes are not signed. See `ARCHITECTURE.md`.
- **Language:** English only. A Hindi option was built and then removed at the owner's request.

## 5. Not tested

- Deployment on Netlify itself (no Netlify account was available in the build environment). The site was tested on a local static web server, which serves files the same way.
- Real phones (iPhone and Android). Tests used a desktop Chromium browser at phone size (390 × 844).
- Firefox and Safari.
