# Unhookd: technical architecture

Version exported: Unhookd v2, published 6 November 2026 (`index.html`, 250,823 bytes).

## 1. Overview

Unhookd is a client-side single-page web app. There is no server, no database, no account system, no analytics and no AI. Everything runs in the browser from one HTML file:

- **HTML:** a small shell (`#root` for screens, `#tabs` for the bottom navigation, `#sheet-host` for pop-up sheets, `#toast`, `#fx` canvas for confetti).
- **CSS:** one `<style>` block with design tokens (CSS custom properties) for colours, day and night mode, colour themes, layout and all animations.
- **JavaScript:** one `<script>` block, about 1,700 lines, written as a single immediately-invoked function in strict mode. It holds the state, every screen, every illustration and every interaction.
- **Illustrations:** all artwork (Finn the fish, accessories, the journey map, place stickers, story pictures, icons, logo) is inline SVG generated by JavaScript functions, so there are no image files. Snapshots are exported to `assets/illustrations/` for reuse.
- **Sound:** all sound effects are synthesised at run time with the Web Audio API (oscillator tones for pop, tick, coin, win). There are no audio files.

The file opens with a short document skeleton (`<!doctype html>`, charset and viewport meta tags, and a small reset stylesheet). That skeleton was added by the publishing step and is part of the exported file.

## 2. Code map

The script is organised into labelled sections (search for `/* ----------`):

| Section | Responsibility |
| --- | --- |
| state (top of script) | `blank()` and `sample()` state factories, loading and migrating saved state, `save()` |
| feel: haptics, sound, confetti | `buzz()` (Vibration API), `sfx()` (Web Audio), `burst()`/`rain()` confetti on a canvas, `celebrate()` |
| xp / levels | steps, seeds and level maths, `sticker()` unlocks |
| quests | builds the daily quest list from trackers, medicines, appointments, plans, people and custom quests |
| views | the five tabs: Today, Journey, Care, Learn, Me, plus Calm and onboarding |
| sheets | pop-up sheets: welcome, check-in, strong craving, slip pathway |
| phone: country codes | full country calling-code list and phone formatting |
| learn: picture stories | six one-minute stories with SVG pictures and myth-or-fact quizzes |
| journey map | the nine-place map, scenic routes after slips, place stickers in four tiers |
| substance features | money saved, units avoided, "what's improving" timelines |
| country-aware help, currency | emergency and helpline numbers and currency per country |
| Unhookd Pro (prototype) | simulated Pro tier, insights charts, doctor report |
| render | `render()`, tab switching, `dailyOpen()` |
| v2: people, lock, plans, clinic codes, safety | trusted people, PIN lock, fingerprint, quick hide, if-then plans, ride-the-wave timer, clinic setup codes and QR, safety levels, withdrawal self-check, safety plan, call screen |
| v2 actions | the action table (`FX`) and form handlers (`FXS`) for the v2 features |
| translation layer | dormant. The language feature was removed from the app (`S.lang` is always `"en"`), but its small helper functions remain in the file unchanged |
| Finn's moves, party effects, splash, onboarding | dance moves and party effects, the celebration overlay, splash screen, six-step onboarding and the "all set" screen |
| actions | the global click, submit, change and keyboard handlers |

**Interaction model.** Every interactive element has a `data-act="name:arg1:arg2"` attribute. One delegated click listener on `document` looks the action up, first in the `FX` table and then in a `switch` statement. Forms use `data-form="name"` and one delegated `submit` listener. After a change the app calls `save()` and `render()`, which rebuilds the current screen from state.

**Routing.** The current tab is kept in the URL hash (`#today`, `#journey`, `#care`, `#learn`, `#calm`, `#me`). No server routing is needed.

## 3. State and storage

- All data lives in one JavaScript object `S` and is saved with `localStorage.setItem("focus-recovery-v2", JSON.stringify(S))` after each change. Reads and writes are wrapped in `try/catch`, so the app still runs (without saving) where storage is blocked.
- Storage is per browser and per web address (origin). Data does not sync between devices and does not carry over from the Claude-hosted copy to a new domain.
- Main fields of `S`:

| Field | Holds |
| --- | --- |
| `onboarded`, `demo`, `consent`, `name`, `hurdles` | setup status, sample-data flag, consent date, nickname, chosen ADHD hurdles |
| `xp`, `seeds`, `stickers`, `showups`, `stats` | progress, currency, unlocked rewards (also drive dance moves and party effects), days opened, counters |
| `trackers[]` | one per substance: goal (stop or cut down), start date, daily limit, daily log, usual spend and amount |
| `checkins{}`, `triggers[]`, `slips[]` | daily mood and craving, craving log with triggers, intensity and what helped, slips with map position |
| `qdone{}`, `custom{}`, `daily[]` | completed quests per day, one-off and daily custom quests |
| `clinic{}`, `appt`, `meds[]` | clinic details (name, doctor, country code, phone, booking link, address, hours), next appointment, medicines and times |
| `people[]`, `hellos[]`, `helloFreq`, `helloPause` | trusted people and the history of hellos sent |
| `plans[]`, `planFollow`, `lastRehearse` | if-then plans with use and "helped" counts, pending follow-up |
| `lock{}` | PIN, discreet mode, auto-lock delay, recovery words, fingerprint credential ID |
| `safety{}`, `escLog[]`, `escHide`, `escFollow`, `heavy`, `wd` | personal safety plan, alert history, follow-ups, heavy-drinking flag, withdrawal self-check result |
| `owned{}`, `equip{}`, `party`, `fav{}` | shop purchases, equipped theme and accessory, celebration mode, favourite move and effect |
| `pro`, `difficulty`, `mode`, `sound`, `haptic`, `notif`, `pace`, `read{}` | Pro simulation, quest level, day or night mode, feedback settings, breathing pace, stories read |

**Security note for production.** `localStorage` is not encrypted. The PIN, recovery words and all health data are stored in plain text on the device. The PIN lock is a privacy screen, not encryption. A production app should use encrypted on-device storage (planned for the native version).

## 4. Browser APIs used

| API | Used for | Notes |
| --- | --- | --- |
| `localStorage` | saving all data | per origin |
| Web Audio (`AudioContext`) | sound effects | starts after the first tap, as browsers require |
| Vibration (`navigator.vibrate`) | haptic feedback | works in Android browsers; not supported by iPhone Safari |
| Canvas 2D | confetti, QR decoding, poster image | |
| Clipboard (`navigator.clipboard.writeText`) | copy number, message, code, report | needs https or localhost; falls back to a "select to copy" message |
| Speech synthesis (`speechSynthesis`) | read aloud | uses the phone's own voices; voice quality varies by device |
| WebAuthn (`navigator.credentials`) | fingerprint or face unlock | platform authenticator only; shows an explanation screen where not available |
| File input with `capture` + `createImageBitmap` | scanning a clinic QR from the camera or a photo | decoded locally with jsQR |
| `window.open` | WhatsApp, text message and phone dialer links | |
| `visibilitychange` | auto-lock after leaving the app | |
| `matchMedia('(prefers-reduced-motion)')` | turns off animations for people who ask their phone to reduce motion | |

## 5. External services and libraries

| Dependency | Where | Required? | Fallback if unavailable |
| --- | --- | --- | --- |
| Google Fonts (Nunito, Baloo 2) | `<link>` in `index.html` | No | system fonts; `index-selfhosted.html` uses `vendor/fonts/` |
| qrcodejs 1.0.0 (cdnjs) | `<script>` in `index.html` | Only to draw the clinic QR image | the plain text code is shown; `index-selfhosted.html` uses `vendor/qrcodejs/` |
| jsQR 1.4.0 (jsDelivr) | loaded on demand when scanning a QR | Only for scanning | message asking the user to type the code; `index-selfhosted.html` uses `vendor/jsqr/` |
| WhatsApp (`wa.me`), SMS, phone dialer | trusted-people hellos, calls | Only when the user taps | copy-message and call screens |
| Google Maps search links | "Directions" to the clinic | Only when tapped | none needed |
| findahelpline.com link | shown when no helpline is listed for a country | Only when tapped | none needed |

There are no calls to any Claude or Anthropic service. One optional hook, `window.claude.use("downloads")`, is tried when saving the clinic poster; outside Claude it is absent and the app uses a normal browser download instead (see `NOT_EXPORTED_AND_DEPENDENCIES.md`).

## 6. Clinic setup codes

A clinic code is `UH1-` followed by URL-safe Base64 of a small JSON object (`n` name, `d` doctor, `p` phone, `c` country, `b` booking link, `a` address, `h` hours, `ap` appointment, `m` medicines). It is encoded and decoded entirely in the browser. It is not signed or encrypted, so a production version should add a signature to prevent tampering.

## 7. Design system

- **Fonts:** Baloo 2 (headings, 600 to 800) and Nunito (body, 500 to 800).
- **Colour tokens:** `--pri` (theme colour; Grape `#6C4CF5` by default, plus Ocean, Jungle, Berry and Midnight), `--pri-soft`, `--bg`, `--card`, `--chip`, `--line`, `--ink`, `--ink2`, and candy accents `--sun`, `--mint`, `--gum`, `--sky`, `--lime`, `--lilac`. Day mode is the default; night mode redefines the tokens under `[data-mode="dark"]`.
- **Layout:** one phone-width column (maximum about 460px) centred on larger screens, a floating pill tab bar, rounded cards (18 to 32px radius), 44px minimum tap targets, safe-area insets for notched phones.
- **Motion:** CSS keyframe animations for Finn's ten dance moves, party effects, the splash screen, quest pops and map details. All are switched off when the phone asks for reduced motion.
